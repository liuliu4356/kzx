# 第一章 认识X项目

## 1.1 项目是什么

X项目（GDB巡检系统）是一套**自动化运维巡检工具**，它能够：

- 定时从你的 **Prometheus** 拉取服务器指标（CPU、内存、磁盘等），判断是否超过阈值
- 定时从你的 **Elasticsearch** 查询日志，检测是否有异常错误日志
- 用 **AI 大模型**（或本地知识库）对采集到的异常进行智能分析，给出处置建议
- 自动生成 HTML 或 Markdown 格式的**巡检报告**
- 通过**邮件/企业微信/飞书**发送报告通知

> **一句话**：你原来需要人工登录 Grafana 看图、翻 Kibana 找日志、写巡检报告，X项目把这些事全部自动化了。

## 1.2 与已有监控体系的关系

```
你现有的环境：
  ┌─────────────────┐      ┌─────────────────┐
  │ Prometheus      │      │ Elasticsearch   │
  │ + Grafana       │      │ + Logstash      │
  │  (指标监控)     │      │ + Filebeat      │
  │                 │      │ + Kibana        │
  └────────┬────────┘      └────────┬────────┘
           │ 读取指标               │ 读取日志
           └──────────┬─────────────┘
                      ▼
           ┌──────────────────────┐
           │   X项目（本手册）    │
           │   自动巡检 + AI分析  │
           │   生成巡检报告       │
           └──────────────────────┘
```

**X项目不修改、不替换你现有的监控系统**，只是从它们**读取数据**，做二次分析。

## 1.3 部署方式说明

本手册采用**本地直接部署**（无 Docker），适合：
- 内网离线环境
- 已有 Python 环境的麒麟服务器
- 不方便或不允许安装 Docker 的场景

X项目只是一个 Python 程序，**不需要安装任何数据库或中间件**，只需 Python 3.10+。

# 第二章 环境准备

## 2.1 硬件要求（最低配置）

| 项目 | 最低要求 | 推荐 |
|------|---------|------|
| CPU | 2核 | 4核 |
| 内存 | 2 GB | 4 GB |
| 磁盘 | 20 GB 可用空间 | 50 GB |
| 网络 | 能访问 Prometheus 和 ES | 百兆以上 |

> 巡检程序本身非常轻量，主要消耗在网络请求上。

## 2.2 确认操作系统版本

```bash
# 查看麒麟系统版本
cat /etc/kylin-release 2>/dev/null || cat /etc/os-release

# 查看内核版本
uname -r

# 查看CPU架构（x86_64 / aarch64）
uname -m
```

**预期输出示例：**
```
Kylin Linux Advanced Server V10 (Tercel)
4.19.90-...
x86_64
```

本手册同时适用于 **x86_64** 和 **aarch64（鲲鹏/飞腾）** 架构。

## 2.3 检查并安装 Python 3.10+

**第一步：检查当前 Python 版本**

```bash
python3 --version
```

如果输出 `Python 3.10.x` 或更高版本，**跳过本节**，直接进入 2.4。

如果输出 `Python 3.6/3.8` 或提示命令不存在，按以下步骤安装。

---

**第二步（麒麟V10 x86_64）：通过包管理器安装**

```bash
# 更新软件包列表
sudo yum update -y

# 安装 Python 3.10（麒麟V10 SP3 已内置，直接安装）
sudo yum install -y python310 python310-pip python310-devel

# 创建 python3 软链接（如果 python3 还指向旧版本）
sudo ln -sf /usr/bin/python3.10 /usr/local/bin/python3
sudo ln -sf /usr/bin/pip3.10 /usr/local/bin/pip3

# 验证
python3 --version     # 应输出 Python 3.10.x
pip3 --version        # 应输出 pip xx.x
```

---

**第二步（麒麟V10 aarch64/鲲鹏，包管理器无 Python 3.10 时）：源码编译**

```bash
# 安装编译依赖
sudo yum install -y gcc gcc-c++ make zlib-devel bzip2-devel \
  openssl-devel ncurses-devel sqlite-devel readline-devel \
  tk-devel libffi-devel wget

# 下载 Python 3.10 源码（选择可访问的镜像）
wget https://mirrors.huaweicloud.com/python/3.10.14/Python-3.10.14.tgz

# 解压编译安装
tar -xzf Python-3.10.14.tgz
cd Python-3.10.14

./configure --prefix=/usr/local/python310 --enable-optimizations
make -j4
sudo make altinstall

# 创建软链接
sudo ln -sf /usr/local/python310/bin/python3.10 /usr/local/bin/python3
sudo ln -sf /usr/local/python310/bin/pip3.10 /usr/local/bin/pip3

# 验证
python3 --version
```

## 2.4 配置 pip 国内镜像（重要，内网也适用）

## 2.5 安装 git


# 第四章 安装Python依赖

## 4.1 创建虚拟环境（推荐）

使用虚拟环境可以避免污染系统 Python 环境，也方便管理依赖版本。

```bash
# 确保在项目目录
cd /opt/kzx

# 创建虚拟环境
python3 -m venv venv

# 激活虚拟环境
source venv/bin/activate

# 激活成功后，命令提示符前会显示 (venv)
# 例如：(venv) [root@kylin kzx]#
```

> **注意**：每次重新登录服务器后，需要重新执行 `source venv/bin/activate` 激活虚拟环境，或者使用后面第八章介绍的 systemd 服务方式。

## 4.2 安装依赖包

```bash
# 确保虚拟环境已激活（提示符前有 (venv)）
# 使用国内镜像安装，速度更快
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

**安装过程约需 1-3 分钟**，看到如下输出表示成功：

```
Successfully installed fastapi-0.x uvicorn-0.x httpx-0.x pyyaml-6.x ...
```

## 4.3 离线安装方案（内网完全隔离时）

**在有网络的机器上打包依赖：**

```bash
# 有网络的机器执行
pip download -r requirements.txt -d ./offline_packages/ \
  -i https://mirrors.aliyun.com/pypi/simple/

# 将 offline_packages 目录传到内网服务器
```

**在麒麟服务器上离线安装：**

```bash
pip install --no-index --find-links=./offline_packages/ -r requirements.txt
```

## 4.4 验证安装

```bash
# 测试各核心模块是否可以导入
python3 -c "import fastapi, uvicorn, httpx, yaml, anthropic; print('✅ 所有依赖安装成功')"
```

如果输出 `✅ 所有依赖安装成功`，说明安装正确。

# 第五章 连接你的Prometheus

## 5.1 找到你的 Prometheus 地址

在已有监控环境中，Prometheus 一般运行在某台服务器的 9090 端口。

```bash
# 在部署了 Prometheus 的服务器上执行（或让同事告诉你地址）
# 查找 Prometheus 进程
ps aux | grep prometheus | grep -v grep

# 或查找 9090 端口监听
netstat -tlnp | grep 9090
```

你需要的是类似 `http://10.0.0.1:9090` 这样的地址（内网 IP + 端口 9090）。

**测试连通性：**

```bash
# 在麒麟服务器上测试
curl -s "http://10.0.0.1:9090/-/healthy"
# 正常返回：Prometheus is Healthy.

# 测试是否能查询指标
curl -s "http://10.0.0.1:9090/api/v1/query?query=up" | python3 -m json.tool | head -20
```

## 5.2 通过 Web 界面配置连接

启动 Web 服务后（第八章），进入**系统设置 → 数据源连接**，点击「添加数据源」：

| 字段 | 填写内容 |
|------|---------|
| 数据源名称 | 主机房-Prometheus（自定义） |
| 类型 | Prometheus |
| 地址 | http://10.0.0.1:9090（替换为实际地址） |
| 超时（秒） | 10 |

## 5.3 通过配置文件配置（可选）

也可以直接编辑 `config.yaml`（在启动前提前配置）：

```yaml
prometheus:
  url: http://10.0.0.1:9090   # ← 改为你的实际地址
  timeout_sec: 10
```

# 第六章 连接你的Elasticsearch

## 6.1 找到你的 ES 地址

ELFK 中，Elasticsearch 通常监听 9200 端口。

```bash
# 测试 ES 连通性
curl -s "http://10.0.0.2:9200/_cluster/health?pretty"
```

**正常输出示例（无认证的 ES）：**

```json
{
  "cluster_name" : "my-cluster",
  "status" : "green",
  "number_of_nodes" : 3,
  ...
}
```

## 6.2 ES 是否开启了认证？

**无认证（常见于内网测试环境）：** 直接使用地址即可。

**有认证（X-Pack Security 开启）：** 需要用户名和密码。

```bash
# 有认证时的测试命令
curl -u 用户名:密码 "http://10.0.0.2:9200/_cluster/health?pretty"
```

## 6.3 通过 Web 界面配置连接

进入**系统设置 → 数据源连接**，点击「添加数据源」：

| 字段 | 填写内容 |
|------|---------|
| 数据源名称 | 主机房-ES（自定义） |
| 类型 | Elasticsearch |
| 地址 | http://10.0.0.2:9200 |
| 用户名环境变量 | ES_USER（如无认证则留空） |
| 密码环境变量 | ES_PASS（如无认证则留空） |

> **安全提示**：密码不直接填入配置文件，而是填写**环境变量名**，实际密码通过环境变量传入。

**设置环境变量（有认证时）：**

```bash
# 临时设置（当前会话有效）
export ES_USER=elastic
export ES_PASS=your_password_here

# 永久设置（写入启动脚本或 systemd 配置）
echo 'export ES_USER=elastic' >> /etc/profile.d/xproject.sh
echo 'export ES_PASS=your_password_here' >> /etc/profile.d/xproject.sh
source /etc/profile.d/xproject.sh
```

## 6.4 配置 Kibana 地址（可选）

如果配置了 Kibana 地址，巡检报告中的 ES 日志条目会自动生成 Kibana 跳转链接，方便直接在 Kibana 查看详细日志。

```yaml
# config.yaml
elasticsearch:
  url: http://10.0.0.2:9200
  kibana_url: http://10.0.0.3:5601   # ← 可选：Kibana 地址
```

# 第七章 初始化配置文件

## 7.1 生成初始配置文件

如果你是第一次使用，可以通过命令行生成一份初始配置：

```bash
# 确保虚拟环境已激活
cd /opt/kzx
source venv/bin/activate

# 生成初始配置（会创建 config.yaml，如果已存在则跳过）
python3 -m src.main init-config
```

或者直接复制示例文件：

```bash
cp config.example.yaml config.yaml
```

## 7.2 config.yaml 核心结构说明

`config.yaml` 是整个项目的唯一配置入口，结构如下：

```yaml
# ============================================================
# 数据源连接（多条）
# ============================================================
datasources:
  - id: prom-main           # 唯一ID（自定义，不能重复）
    type: prometheus        # 类型：prometheus 或 elasticsearch
    name: 主机房-Prometheus  # 显示名称
    url: http://10.0.0.1:9090
    timeout_sec: 10

  - id: es-main
    type: elasticsearch
    name: 主机房-ES
    url: http://10.0.0.2:9200
    username_env: ES_USER   # 有认证时填环境变量名，无认证留空
    password_env: ES_PASS

# ============================================================
# 机房配置（可多个，对应巡检采集单元）
# ============================================================
sites:
  - label: 主机房
    prometheus_url: http://10.0.0.1:9090
    es_url: http://10.0.0.2:9200

# ============================================================
# Prometheus 巡检指标
# ============================================================
prometheus:
  url: http://10.0.0.1:9090  # 单机房时使用，多机房时被 sites 覆盖
  timeout_sec: 10
  queries:
    - name: cpu_usage
      promql: 100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
      threshold: 10
      unit: "%"
      anomaly_when: gt      # gt=大于阈值告警, lt=小于阈值告警
      description: CPU使用率

# ============================================================
# Elasticsearch 日志查询
# ============================================================
elasticsearch:
  url: http://10.0.0.2:9200
  kibana_url: http://10.0.0.3:5601   # 可选
  username_env: ES_USER
  password_env: ES_PASS
  queries:
    - name: error_logs
      index: app-logs-*
      query: level:ERROR OR level:FATAL
      time_range_hours: 24
      top_n: 5
      description: 应用错误日志

# ============================================================
# AI 大模型（可不配置，无AI时用知识库）
# ============================================================
llm:
  active_model: claude-main
  models:
    - id: claude-main
      name: Claude Sonnet
      provider: anthropic
      model: claude-sonnet-4-6
      api_key_env: ANTHROPIC_API_KEY

# ============================================================
# 报告配置
# ============================================================
report:
  output_dir: reports
  filename_format: "{date}-{time}"
  retention_days: 30

# ============================================================
# 通知配置（可不配置）
# ============================================================
notifiers:
  - type: email
    enabled: false
    smtp_host: smtp.example.com
    smtp_port: 465
    smtp_ssl: true
    sender: noreply@example.com
    recipients:
      - admin@example.com
```

## 7.3 最简可用配置（快速启动）

如果你只想先跑起来看看效果，最简配置只需填写数据源地址：

```yaml
prometheus:
  url: http://你的Prometheus地址:9090
  timeout_sec: 10
  queries:
    - name: cpu_usage
      promql: 100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
      threshold: 80
      unit: "%"
      anomaly_when: gt
      description: CPU使用率

elasticsearch:
  url: http://你的ES地址:9200
  queries:
    - name: error_logs
      index: "*"
      query: level:ERROR
      time_range_hours: 24
      top_n: 5
      description: 错误日志

report:
  output_dir: reports
  filename_format: "{date}-{time}"
```

> **提示**：Prometheus 指标和 ES 查询都可以在 Web 界面可视化配置，不需要手动编辑 YAML。建议先启动 Web 界面，再通过界面完成完整配置。

# 第八章 启动Web服务

## 8.1 直接启动（开发/测试用）

```bash
# 确保在项目目录且虚拟环境已激活
cd /opt/kzx
source venv/bin/activate

# 启动 Web 服务（默认监听 0.0.0.0:8000）
python3 -m src.main web
```

**正常启动输出：**

```
INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
```

在麒麟服务器上浏览器访问：`http://本机IP:8000`

> 如果是远程访问，把 `本机IP` 替换为麒麟服务器的实际 IP 地址。

**常用启动选项：**

```bash
# 指定端口（如果 8000 被占用）
python3 -m src.main web --port 8080

# 仅本机访问（更安全）
python3 -m src.main web --host 127.0.0.1

# 开发模式（代码修改后自动重启）
```

# 第十章 巡检指标规则配置详解

## 10.1 Prometheus 指标配置要点

### 10.1.1 PromQL 编写原则

X项目的 Prometheus 采集会对查询结果取所有时序的**最大值**（anomaly_when=gt 时）或**最小值**（anomaly_when=lt 时）作为代表值进行阈值判断。

因此 PromQL 应返回**已计算好的指标值**（如百分比、绝对数值），而不是原始计数器。

**正确写法（返回百分比）：**
```
100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```

**错误写法（返回原始累计计数，无法直接与阈值比较）：**
```
node_cpu_seconds_total{mode="idle"}
```

### 10.1.2 常用指标 PromQL 参考

**CPU 使用率（%）：**
```
100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```
阈值建议：80（生产可设 10）

**内存使用率（%）：**
```
(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100
```
阈值建议：85（生产可设 60）

**磁盘使用率（%）：**
```
(1 - node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100
```
阈值建议：85（生产可设 80）

**系统负载（load5 每核）：**
```
avg by(instance)(node_load5) / count by(instance)(node_cpu_seconds_total{mode="idle"})
```
阈值建议：0.8（64核服务器对应 load5 < 51.2）

**实例存活（up=0 表示宕机）：**
```
up{job="node"}
```
anomaly_when: lt，阈值：1

**MySQL 连接数：**
```
mysql_global_status_threads_connected
```
阈值建议：根据实际 max_connections 设置，通常为上限的 60%

**网络流量（Mb/s，发+收合计）：**
```
(rate(node_network_receive_bytes_total{device!="lo"}[5m]) + rate(node_network_transmit_bytes_total{device!="lo"}[5m])) / 1024 / 1024 * 8
```
阈值建议：100（网络带宽 25Gbps 时设 100Mbps）

### 10.1.3 告警条件（anomaly_when）说明

| 值 | 触发条件 | 适用场景 |
|----|---------|---------|
| gt | 指标值 > 阈值 | CPU/内存/磁盘使用率过高 |
| lt | 指标值 < 阈值 | 实例存活检查（up < 1） |

## 10.2 ES 日志查询配置要点

### 10.2.1 Lucene 查询语法速查

| 场景 | 查询语句 |
|------|---------|
| 查 ERROR 级别 | `level:ERROR` |
| 查 ERROR 或 FATAL | `level:ERROR OR level:FATAL` |
| 排除某个词 | `level:ERROR NOT message:"connect refused"` |
| 查包含某词的消息 | `message:"OutOfMemoryError"` |
| 查某个服务的错误 | `service:payment-service AND level:ERROR` |
| 查慢查询（MySQL） | `message:"Slow query"` |
| 查连接断开 | `message:"Lost connection" OR message:"Connection reset"` |

### 10.2.2 索引名称填写规则

| 场景 | 索引填写示例 |
|------|------------|
| 所有日志 | `*` 或 `*-*` |
| 特定应用 | `app-logs-*` |
| 特定日期格式 | `logstash-2026.*` |
| 多个索引 | `app-*,sys-*` |

### 10.2.3 时间范围（time_range_hours）选择建议

| 巡检频率 | 建议时间范围 |
|---------|------------|
| 每小时一次 | 1-2 小时 |
| 每天一次（日常巡检） | 24 小时 |
| 每周一次 | 168 小时 |

### 10.2.4 「可忽略」标志的使用

对于已知的噪音日志（例如已知的第三方组件报错、系统正常退出日志等），勾选「可忽略」后：

- 报告中仍会显示该查询的命中数，但标注「已知/可忽略」
- AI 分析时会跳过该查询，不计入告警评分
- 有助于减少误报

## 10.3 批量导入指标配置

如果有多台服务器需要巡检同样的指标，可以先在一台上配好，导出 JSON，再在其他台导入。

**导出步骤：**

1. 左侧菜单 → 巡检指标 → 导出配置
2. 勾选要导出的内容（Prometheus指标 / ES查询）

3. 勾选是否覆盖现有配置

## 11.3 配置 crontab 定时巡检

通过 crontab 可以让系统每天自动执行巡检并发送报告。

**第一步：创建巡检脚本**

```bash
cat > /opt/kzx/run_inspect.sh << 'EOF'
#!/bin/bash
cd /opt/kzx
source venv/bin/activate
python3 -m src.main inspect --format html >> /opt/kzx/logs/cron.log 2>&1
EOF

chmod +x /opt/kzx/run_inspect.sh

# 创建日志目录
mkdir -p /opt/kzx/logs
```

**第二步：添加 crontab 任务**

```bash
crontab -e
```

在编辑器中添加以下行（每天早上 8 点执行）：

```
0 8 * * * /opt/kzx/run_inspect.sh
```

其他常用时间格式：

```
# 每天 8:00 和 20:00 各巡检一次
0 8,20 * * * /opt/kzx/run_inspect.sh

# 工作日（周一到周五）8:00 巡检
0 8 * * 1-5 /opt/kzx/run_inspect.sh

# 每小时巡检一次
0 * * * * /opt/kzx/run_inspect.sh
```

**第三步：验证 crontab**

```bash
# 查看当前 crontab
crontab -l

# 手动测试脚本是否正常运行
/opt/kzx/run_inspect.sh

# 查看执行日志
tail -f /opt/kzx/logs/cron.log
```

# 第十二章 常见问题排查

## 12.1 Web 服务无法访问

**现象**：浏览器访问 `http://服务器IP:8000` 提示连接超时或拒绝连接。

**排查步骤：**

```bash
# 1. 确认服务是否在运行
sudo systemctl status xproject
# 或
ps aux | grep "src.main web" | grep -v grep

# 2. 确认端口是否在监听
netstat -tlnp | grep 8000
# 期望看到：tcp 0.0.0.0:8000 LISTEN

# 3. 本机测试
curl -s http://localhost:8000/
# 如果本机正常但远程不行，说明是防火墙问题

# 4. 检查防火墙
sudo firewall-cmd --list-ports | grep 8000
# 如果没有，执行：
sudo firewall-cmd --permanent --add-port=8000/tcp
sudo firewall-cmd --reload
```

## 12.2 点击「开始巡检」无反应或报错

**现象**：点击后进度条不动，或提示 500 错误。

**排查步骤：**

```bash
# 查看服务日志
sudo journalctl -u xproject -n 100 --no-pager
# 或如果是直接启动：
# 查看终端输出
```

**常见原因和解决方法：**

| 错误信息 | 原因 | 解决方法 |
|---------|------|---------|
| `Connection refused http://...9090` | Prometheus 地址不通 | 确认地址和端口，检查网络 |
| `Connection refused http://...9200` | ES 地址不通 | 同上 |
| `No queries configured` | 没有配置任何巡检指标 | 先在 Web 界面添加指标 |
| `NameError` / `ImportError` | Python 依赖缺失 | 重新执行 `pip install -r requirements.txt` |

## 12.3 Prometheus 数据采集失败

**现象**：报告中显示某指标「采集失败」或「连接超时」。

```bash
# 手动测试 Prometheus 连通性
curl -s "http://你的Prometheus地址:9090/-/healthy"
# 期望返回：Prometheus is Healthy.

# 测试 PromQL 是否有效
curl -s "http://你的Prometheus地址:9090/api/v1/query?query=up" \
  | python3 -m json.tool | head -30
```

**PromQL 返回结果为空（resultType=vector, result=[]）：**

可能原因：
1. 该指标在 Prometheus 中不存在，用 Grafana 验证 PromQL 是否有数据
2. 标签选择器过严，例如 `{job="node"}` 但实际 job 名是 `node-exporter`

```bash
# 查询所有指标名（找到正确的指标名）
curl -s "http://Prometheus地址:9090/api/v1/label/__name__/values" \
  | python3 -m json.tool | grep -i cpu | head -10
```

## 12.4 Elasticsearch 查询失败

**现象**：报告中 ES 查询「连接失败」或「认证失败」。

```bash
# 无认证测试
curl -s "http://ES地址:9200/_cluster/health?pretty"

# 有认证测试（替换实际用户名密码）
curl -u elastic:密码 "http://ES地址:9200/_cluster/health?pretty"
```

**401 Unauthorized 错误：**

```bash
# 确认环境变量已设置
echo $ES_USER
echo $ES_PASS

# 如果为空，重新设置
export ES_USER=elastic
export ES_PASS=你的密码

# 如果使用 systemd，在服务文件中添加 Environment 行，然后重启
sudo systemctl restart xproject
```

**索引不存在（index_not_found_exception）：**

```bash
# 查看所有索引
curl -s "http://ES地址:9200/_cat/indices?v" | head -20
# 找到实际的索引名，修正配置中的索引字段
```

## 12.5 AI 分析不工作

**现象**：报告生成了但没有 AI 分析节，或提示 API 错误。

```bash
# 确认环境变量已设置
echo $ANTHROPIC_API_KEY
# 期望输出：sk-ant-xxxx...（非空）

# 如果为空
export ANTHROPIC_API_KEY=sk-ant-你的密钥
```

**无法访问外网 API：**

对于完全内网环境，可以：
1. 配置内网部署的 OpenAI 兼容接口（如内网 Qwen/文心）
2. 不配置 AI，改用知识库（上传相关文档）
3. 使用 `--skip-llm` 参数跳过 AI 分析

## 12.6 报告生成失败

**现象**：巡检完成但报告列表为空，或报告目录没有新文件。

```bash
# 检查报告目录权限
ls -la /opt/kzx/reports/

# 如果目录不存在
mkdir -p /opt/kzx/reports

# 如果权限不够
chmod 755 /opt/kzx/reports
```

## 12.7 Python 依赖安装失败

**现象**：`pip install` 报错 `Could not find a version` 或超时。

```bash
# 切换不同的国内镜像
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple/
# 或
pip install -r requirements.txt -i https://mirrors.163.com/pypi/simple/

# 如果是编译类依赖报错，先安装编译工具
sudo yum install -y gcc gcc-c++ python3-devel

# 检查 pip 版本并升级
pip3 install --upgrade pip
```

## 12.8 服务启动时端口被占用

**现象**：`Address already in use` 错误。

```bash
# 查找占用 8000 端口的进程
netstat -tlnp | grep 8000
# 或
ss -tlnp | grep :8000

# 终止旧进程（替换 <PID>）
kill -9 <PID>

# 确认端口已释放
netstat -tlnp | grep 8000

# 重新启动
python3 -m src.main web
```

## 12.9 虚拟环境每次登录都需要重新激活

这是正常现象。有两种解法：

**方法一：写入 .bashrc（自动激活）**

```bash
echo "source /opt/kzx/venv/bin/activate" >> ~/.bashrc
source ~/.bashrc
```

**方法二：使用 systemd 服务**（推荐生产环境）

按第八章 8.2 节配置 systemd 服务，服务中直接使用 venv 的绝对路径，无需手动激活：

```
ExecStart=/opt/kzx/venv/bin/python3 -m src.main web
```

```yaml
  - label: 主机房
    prometheus_url: http://10.0.0.1:9090

  #   prometheus_url: http://10.1.0.1:9090
  #   es_url: http://10.1.0.2:9200

# Prometheus 全局配置（sites 未配置时使用）

  url: http://10.0.0.1:9090

  queries:
    - name: cpu_usage

      threshold: 80
      unit: "%"
      anomaly_when: gt
      description: CPU使用率
      faq: |
        1. 执行 top -c 查看高CPU进程
        2. 确认是否在批处理窗口（正常波动）
        3. 联系应用负责人确认是否有大任务在运行

    - name: memory_usage
      promql: (1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100
      threshold: 85
      unit: "%"
      anomaly_when: gt
      description: 内存使用率

        1. 执行 free -h 查看内存详情
        2. 执行 ps aux --sort=-%mem | head -10 查看内存占用最高的进程

    - name: disk_usage
      promql: (1 - node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100
      threshold: 85
      unit: "%"
      anomaly_when: gt
      description: 根分区磁盘使用率
      faq: |
        1. 执行 df -h 查看各分区使用情况
        2. 执行 du -sh /* 2>/dev/null | sort -h | tail -10 找出大目录

    - name: system_load
      promql: avg by(instance)(node_load5) / count by(instance)(node_cpu_seconds_total{mode="idle"})
      threshold: 0.8
      unit: ""
      anomaly_when: gt
      description: 系统负载（每核load5）

    - name: instance_up
      promql: up{job="node"}
      threshold: 1
      unit: ""
      anomaly_when: lt
      description: 实例存活状态
      faq: |
        1. 检查对应节点是否宕机
        2. 检查 node_exporter 进程是否在运行
        3. 检查网络连通性

    - name: network_throughput
      promql: (rate(node_network_receive_bytes_total{device!="lo"}[5m]) + rate(node_network_transmit_bytes_total{device!="lo"}[5m])) / 1024 / 1024 * 8
      threshold: 100
```

# 附录B 常用PromQL速查表

## B.1 系统资源指标

| 指标 | PromQL | 单位 | 建议阈值 |
|------|--------|------|---------|
| CPU使用率 | `100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)` | % | 80 |
| 内存使用率 | `(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100` | % | 85 |
| 根分区使用率 | `(1 - node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100` | % | 85 |
| 数据盘使用率 | `(1 - node_filesystem_avail_bytes{mountpoint="/data"} / node_filesystem_size_bytes{mountpoint="/data"}) * 100` | % | 80 |
| 系统负载/核 | `avg by(instance)(node_load5) / count by(instance)(node_cpu_seconds_total{mode="idle"})` | - | 0.8 |
| 实例存活 | `up{job="node"}` | - | lt:1 |

## B.2 网络指标

| 指标 | PromQL | 单位 |
|------|--------|------|
| 入流量 | `rate(node_network_receive_bytes_total{device!="lo"}[5m]) / 1024 / 1024 * 8` | Mb/s |
| 出流量 | `rate(node_network_transmit_bytes_total{device!="lo"}[5m]) / 1024 / 1024 * 8` | Mb/s |
| 收发合计 | `(rate(node_network_receive_bytes_total{device!="lo"}[5m]) + rate(node_network_transmit_bytes_total{device!="lo"}[5m])) / 1024 / 1024 * 8` | Mb/s |

## B.3 磁盘IO指标

| 指标 | PromQL | 单位 |
|------|--------|------|
| 读延迟 | `rate(node_disk_read_time_seconds_total[5m]) / rate(node_disk_reads_completed_total[5m]) * 1000` | ms |
| 写延迟 | `rate(node_disk_write_time_seconds_total[5m]) / rate(node_disk_writes_completed_total[5m]) * 1000` | ms |
| IO利用率 | `rate(node_disk_io_time_seconds_total[5m]) * 100` | % |

## B.4 MySQL 指标（mysql_exporter）

| 指标 | PromQL | 说明 |
|------|--------|------|
| 连接数 | `mysql_global_status_threads_connected` | 当前连接数 |
| QPS | `rate(mysql_global_status_questions[5m])` | 每秒查询数 |
| TPS | `rate(mysql_global_status_com_commit[5m]) + rate(mysql_global_status_com_rollback[5m])` | 每秒事务数 |
| 慢查询/秒 | `rate(mysql_global_status_slow_queries[5m])` | 慢查询速率 |
| 复制延迟 | `mysql_slave_status_seconds_behind_master` | 主从延迟秒数 |

## B.5 PromQL 调试技巧

```bash
# 在 Prometheus 页面（http://Prometheus地址:9090）直接输入 PromQL 调试
# 或通过命令行：

# 查询当前值
curl -s "http://10.0.0.1:9090/api/v1/query?query=up" | python3 -m json.tool

# URL 编码复杂 PromQL（Python 辅助）
python3 -c "

print(urllib.parse.quote(q))
"

```

# 附录C 常用ES查询速查表

## C.1 日志级别查询

| 场景 | Lucene 查询 |
|------|------------|
| ERROR 日志 | `level:ERROR` |
| FATAL 日志 | `level:FATAL` |
| ERROR 或 FATAL | `level:ERROR OR level:FATAL` |
| WARN 日志 | `level:WARN OR level:WARNING` |
| 所有异常级别 | `level:(ERROR OR FATAL OR WARN)` |

## C.2 按消息内容查询

| 场景 | Lucene 查询 |
|------|------------|
| 包含特定词 | `message:"OutOfMemoryError"` |
| 慢查询 | `message:"Slow query"` |
| 连接断开 | `message:"Lost connection"` |
| 连接拒绝 | `message:"Connection refused"` |
| 锁等待超时 | `message:"Lock wait timeout"` |
| 死锁 | `message:deadlock` |
| OOM | `message:"OutOfMemoryError" OR message:"GC overhead"` |

## C.3 组合查询

| 场景 | Lucene 查询 |
|------|------------|
| 特定服务的错误 | `service:payment AND level:ERROR` |
| 排除已知噪音 | `level:ERROR NOT message:"Connection reset by peer"` |
| 多个关键词 | `message:(timeout OR "connection refused" OR "no route")` |
| 按主机查 | `host:server-01 AND level:ERROR` |

## C.4 常见索引模式

| 日志来源 | 常见索引名模式 |
|---------|-------------|
| Logstash 输出 | `logstash-YYYY.MM.DD` |
| Filebeat 输出 | `filebeat-*` 或 `app-logs-*` |
| 自定义应用 | `应用名-YYYY.MM` |
| 全量查询 | `*` |

## C.5 通过 Kibana 验证查询

在配置 ES 查询前，建议先在 Kibana 中验证：

1. 打开 Kibana（`http://ES地址:5601`）

3. 选择时间范围（右上角）
4. 在搜索框输入 Lucene 查询语句
5. 确认能查到预期日志
6. 将验证通过的查询语句填入 X项目配置
