# 三思GDB巡检平台 — 开发者指南

> 本文档面向希望参与贡献或二次开发的工程师，介绍项目架构、模块设计、
> 开发环境搭建和扩展方法。

## 1. 技术栈一览

| 层次 | 技术 | 说明 |
|---|---|---|
| CLI 入口 | Click + Python | `src/main.py`，命令行工具 |
| Web 框架 | FastAPI + Uvicorn | `src/web/app.py`，RESTful + SSE |
| 模板引擎 | Jinja2 | HTML/Markdown 报告双格式 |
| 数据采集 | httpx（异步 HTTP） | Prometheus API + ES REST API |
| AI 分析 | Anthropic Python SDK | Claude 模型，Prompt Caching |
| 配置管理 | PyYAML + dataclass | 强类型配置结构 |
| 并发 | ThreadPoolExecutor | 多机房并行采集 |

## 3. 开发环境搭建

### 3.1 克隆仓库

```bash
git clone https://github.com/liuliu4356/kzx.git
cd kzx
```

### 3.2 创建虚拟环境

```bash
python3 -m venv .venv
source .venv/bin/activate        # Linux/macOS
# .venv\Scripts\activate.bat    # Windows CMD
# .venv\Scripts\Activate.ps1   # PowerShell
```

### 3.3 安装依赖

```bash
pip install -r requirements.txt
```

主要依赖：

```
fastapi          # Web 框架
uvicorn[standard] # ASGI 服务器
httpx            # 异步 HTTP 客户端
anthropic        # Claude API SDK
jinja2           # 模板引擎
pyyaml           # YAML 解析
click            # CLI 框架
python-dotenv    # .env 加载
python-multipart # 表单上传
```

### 3.4 配置本地开发环境

```bash
cp config.example.yaml config.yaml

# 设置 API Key
export ANTHROPIC_API_KEY="sk-ant-xxxx"

# 如果没有 Prometheus/ES，可使用 mock 测试（见 mock/ 目录）
```

### 3.5 启动开发服务器

```bash
# Web 服务（热重载）
python3 -m src.main web --reload

# 触发一次巡检（不调用 AI）
python3 -m src.main inspect --skip-llm --no-notify
```

## 4. 核心数据流

```
用户触发巡检（CLI inspect / Web API /api/inspect）
  │
  ├─ 1. load_config()          从 config.yaml 解析所有配置
  │
  ├─ 2. collect_sites()        多机房并发采集
  │      ├─ 快照模式：prometheus.collect() + elasticsearch.collect()
  │      └─ 时间段模式：prometheus_range.collect() + elasticsearch.collect()
  │
  ├─ 3. analyzer.analyze()     构建 AI payload → Claude API → 返回 Markdown
  │      └─ （可跳过：--skip-llm）
  │
  ├─ 4. reporter.render()      Jinja2 渲染报告（md 或 html）→ 写文件
  │
  └─ 5. notifiers.notify_all() 发送通知（钉钉/飞书/企业微信）
         └─ （可跳过：--no-notify）
```

## 5. 关键模块说明

### 5.1 config.py — 配置结构

所有配置通过 Python dataclass 强类型化：

```python
@dataclass
class PromQuery:
    name: str
    promql: str
    threshold: float
    anomaly_when: str = "gt"   # "gt" 超过阈值异常 / "lt" 低于阈值异常
    unit: str = ""
    description: str = ""
    faq: str = ""

@dataclass
class SiteConfig:
    label: str
    prometheus_url: str
    es_url: str = ""   # 空字符串 → 使用全局 elasticsearch.url

@dataclass
class BatchWindow:
    label: str
    start_hour: int   # UTC 小时
    end_hour: int
    relaxed_thresholds: dict[str, float]
```

`load_config(path)` 从 YAML 文件解析出顶层 `Config` 对象。

### 5.2 collectors/ — 采集层

**`PromResult`（即时快照）核心字段：**

```python
@dataclass
class PromResult:
    name: str
    promql: str
    value: float         # 聚合代表值（多 instance 取 max 或 min）
    threshold: float
    unit: str
    is_anomaly: bool
    error: str = ""      # 采集失败时的错误信息，不中断流程
    faq: str = ""
    description: str = ""
```

**`AnomalyWindow`（时间段审计）核心字段：**

```python
@dataclass
class AnomalyWindow:
    start_ts: str        # ISO UTC 时间
    end_ts: str
    instance: str        # 节点 IP（已去除端口）
    max_value: float
    threshold: float
    duration_minutes: int
```

### 5.3 analyzer.py — AI 分析

调用 Claude API，将采集结果序列化为 JSON payload 注入 User Message，
System Prompt 启用 `cache_control: ephemeral` 以复用缓存。

批处理窗口检测到后，将窗口信息注入 context 节，
AI 据此判断是否降低该时段的告警优先级。

### 5.4 web/config_store.py — 配置 CRUD

封装所有对 `config.yaml` 的读写操作：

```python
def list_sites() -> list[dict]
def save_site(label, prometheus_url, es_url) -> None
def delete_site(label) -> None

def list_datasources() -> list[dict]
def save_datasource(ds: dict) -> None
def delete_datasource(ds_id: str) -> None

def list_llm_models() -> list[dict]
def save_llm_model(model: dict) -> None
def set_active_llm(model_id: str) -> None
```

### 5.5 web/app.py — SSE 流式巡检

巡检触发后，通过 Server-Sent Events 实时向前端推送进度：

```python
@app.get("/api/inspect/stream")
async def inspect_stream():
    def generator():
        yield "data: 加载配置...\n\n"
        # ... 运行采集、分析、报告
        yield "data: DONE:/reports/2026-05-02-0800.html\n\n"
    return StreamingResponse(generator(), media_type="text/event-stream")
```

前端 JS 通过关键词匹配驱动 4 步进度条。

## 6. 扩展开发

### 6.1 添加新的 Prometheus 指标

仅需修改 `config.yaml`，无需改代码：

```yaml
prometheus:
  queries:
    - name: my_new_metric
      promql: 'sum(rate(http_requests_total[5m])) by (instance)'
      threshold: 1000
      anomaly_when: gt
      unit: "req/s"
      description: "HTTP 请求速率"
      faq: |
        1. 检查是否有异常流量
        2. 查看 access.log 确认来源 IP
```

### 6.2 添加新的通知渠道

1. 在 `src/notifiers/` 下新建 `mychannnel.py`：

```python
class MyChannelNotifier:
    def __init__(self, cfg: dict): ...

    def send(self, subject: str, body: str) -> None:
        # 调用通知 API
        ...
```

2. 在 `src/notifiers/__init__.py` 的 `notify_all()` 中注册：

```python
elif item["type"] == "mychannel":
    MyChannelNotifier(item).send(subject, body)
```

### 6.3 添加新的 Web 页面

1. 在 `src/web/templates/` 下新建 `mypage.html`：

```html
{% extends "base.html" %}
{% block page_title %}我的新页面{% endblock %}
{% block page_subtitle %}功能描述{% endblock %}
{% block content %}
<!-- 页面内容 -->
{% endblock %}
```

2. 在 `src/web/app.py` 中添加路由：

```python
@app.get("/mypage", response_class=HTMLResponse)
async def page_mypage(request: Request):
    return render_template("mypage.html", {"active": "mypage"})
```

3. 在 `src/web/templates/base.html` 侧边栏添加菜单项。

### 6.4 添加新的项目总览文档

在 `src/web/app.py` 的 `_OVERVIEW_PAGES` 字典中添加：

```python
"mydoc": {
    "title": "我的文档标题",
    "files": [_PROJ_ROOT / "docs" / "我的文档.md"],
},
```

然后在 `base.html` 的项目总览子菜单中添加链接：

```html
<a href="/overview/mydoc" class="...">我的文档标题</a>
```

## 7. 调试技巧

### 7.1 开启详细日志

```bash
# 设置日志级别
export LOG_LEVEL=DEBUG
python3 -m src.main inspect --skip-llm
```

### 7.2 单独测试 Prometheus 采集

```python
# Python REPL
from src.config import load_config
from src.collectors.prometheus import collect

cfg = load_config("config.yaml")
results = collect(cfg.prometheus)
for r in results:
    print(r.name, r.value, r.is_anomaly)
```

### 7.3 单独测试 ES 查询

```python
from src.collectors.elasticsearch import collect
results = collect(cfg.elasticsearch)
for r in results:
    print(r.name, r.total, r.hits[:2])
```

### 7.4 Mock 数据测试

不需要真实 Prometheus/ES 时，可修改 `config.yaml` 指向 `mock/` 目录下的 mock 服务：

```bash
# 启动 mock 服务（如果存在）
python3 mock/mock_metrics.py
```

## 8. 代码规范

- Python 版本：3.10+，使用 `match/case`、`str | None` 等新语法
- 类型注解：所有函数签名都应有类型注解
- dataclass 优先于 dict 传递结构化数据
- 错误不中断流程：采集失败时写入 `error` 字段，继续执行
- 注释原则：只在 WHY 不明显时写注释，不写 WHAT
- 命令行选项：遵循 `--skip-xxx` / `--no-xxx` 的否定前缀规范
