# 常见问题解答 (FAQ)

> 收集三思GDB巡检平台使用过程中常见问题及解决方案。  
> 问题按场景分类，建议先用 Ctrl+F 搜索关键词。

---

## 第一章 安装与环境

### Q1: pip install 依赖失败或超时

**现象：** `pip install -r requirements.txt` 报网络超时或下载错误。

**解决：**
```bash
# 使用阿里云镜像
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

---

### Q2: Python 版本不满足要求（需 ≥ 3.10）

**现象：** `python3 --version` 输出 3.8 / 3.9。

**解决：**
```bash
# 麒麟 V10（若官方源有 python310）
sudo yum install -y python310 python310-pip

# 或参见《麒麟系统本地部署与实战使用手册》第 3 节从源码编译
```

---

### Q3: Docker 环境下启动失败（WSL 2 报错）

**现象：** Docker Desktop 提示 "WSL 2 installation is required"。

**解决：**
1. 打开 Windows 更新，安装所有更新
2. 以管理员身份运行：`wsl --update`
3. 重启电脑后再启动 Docker Desktop

---

### Q4: 端口被占用，服务无法启动

**现象：** 启动时报 `address already in use` 或 `bind: address in use`。

**解决：**
```bash
# Linux：查找占用端口的进程
ss -tlnp | grep 8000

# Windows：
netstat -ano | findstr "8000"
taskkill /PID <进程ID> /F
```

## 第二章 配置文件

### Q5: 运行巡检提示 `config.yaml not found`

**解决：**
```bash
cp config.example.yaml config.yaml
# 再按实际环境修改 Prometheus 和 ES 地址
```

---

### Q6: config.yaml 修改后没有生效

**原因：** Web 服务已在内存中缓存配置；某些字段修改需重启才能生效。

**解决：**
```bash
# 重启 Web 服务
python3 -m src.main web    # Ctrl+C 停止后重新运行
# 或 systemd 方式：
sudo systemctl restart gdb-inspect
```

---

### Q7: ANTHROPIC_API_KEY 未设置，AI 分析报错

**现象：** 运行巡检时报 `ANTHROPIC_API_KEY is not set` 或 `AuthenticationError`。

**解决：**
```bash
# 临时设置（当前会话有效）
export ANTHROPIC_API_KEY="sk-ant-api03-xxxxxx"

# 永久设置（写入 ~/.bashrc 或 /etc/profile.d/）
echo 'export ANTHROPIC_API_KEY="sk-ant-api03-xxxxxx"' >> ~/.bashrc
source ~/.bashrc

# 或在 config.yaml 中通过 api_key_env 指定环境变量名：
# llm:
#   api_key_env: MY_CLAUDE_KEY
```

> 如无 API Key，可使用 `--skip-llm` 跳过 AI 分析。

## 第三章 Prometheus 采集

### Q8: Prometheus 指标采集返回空（无数据）

**排查步骤：**
1. 访问 http://Prometheus地址:9090
2. 点击 Status → Targets，检查是否有红色 DOWN 的 Target
3. 在 Graph 页面执行基础查询：

```promql
up                            # 实例存活
node_load1                    # 系统负载
node_memory_MemAvailable_bytes # 可用内存
```

**常见原因：**
- 被监控节点 Node Exporter 未安装或未启动
- 网络不通（防火墙阻断 9100 端口）
- `prometheus.yml` 中 `scrape_configs` 未配置该节点

---

### Q9: 指标名称/PromQL 写错，查询无结果

**解决：** 在 Prometheus Web UI → Graph 页面测试 PromQL，确认后再填入 config.yaml。

也可在 Web UI → 巡检指标 → 编辑指标 → 点「🧪 在线测试」即时验证。

---

### Q10: 时间段审计（--period）结果与预期不符

**常见原因：**
- 时段内 Prometheus 数据稀疏（`step_minutes` 太大，漏掉短暂异常）

**解决：**
```yaml
inspection:
  step_minutes: 1   # 缩短采集步长（默认 5 分钟）
```

> 注意：步长越小，查询时间越长；建议日常用 5 分钟，事故复盘用 1 分钟。

## 第四章 Elasticsearch 日志

### Q11: 巡检报告中 ES 部分显示"0 条"

**排查：**
```bash
# 检查 ES 是否正常运行
curl http://ES地址:9200

# 查看索引列表
curl http://ES地址:9200/_cat/indices?v

# 手动执行查询验证
curl -H "Content-Type:application/json" http://ES地址:9200/logstash-*/_search?size=1
```

**常见原因：**
- 索引名称与配置不匹配（默认 `logstash-*`，实际可能是 `filebeat-*` 或自定义）
- 时间字段名不是 `@timestamp`
- ES 未开启或数据为空

---

### Q12: ES 查询报 `AuthorizationException`

**解决：** 在 config.yaml 中配置认证信息：

```yaml
elasticsearch:
  url: "http://10.0.0.1:9200"
  username: "elastic"
  password: "your_password"
```

---

### Q13: 日志缺少 `@timestamp` 字段，时间过滤失效

**解决：** 确保日志写入 ES 时包含 `@timestamp` 字段：
```json
{
  "@timestamp": "2026-05-02T10:00:00Z",
  "level": "ERROR",
  "message": "Connection lost"
}
```

Logstash 通常会自动添加此字段；Filebeat 也会。如使用自定义写入，需手动添加。

## 第五章 Web 界面

### Q14: 访问 http://localhost:8000 返回 Connection Refused

**原因：** Web 服务未启动。

**解决：**
```bash
python3 -m src.main web
# 或后台运行：
nohup python3 -m src.main web > /tmp/gdb-web.log 2>&1 &
```

---

### Q15: Web 界面返回 500 Internal Server Error

**排查：** 查看控制台（或 systemd 日志）报错：

```bash
# systemd 方式
sudo journalctl -u gdb-inspect -n 50

# 直接启动方式
python3 -m src.main web   # 错误信息会打印到终端
```

**常见原因：**
- `config.yaml` 缺失或格式错误（YAML 缩进问题）
- 依赖未安装（`pip install -r requirements.txt`）
- Jinja2 模板语法错误（升级版本后模板未同步）

---

### Q16: 「开始巡检」按钮点击后无反应 / 进度条不动

**排查：**
1. 打开浏览器开发者工具（F12）→ Network，查看 `/api/inspect` 请求是否发出
2. 查看 Response 内容是否有错误信息

**常见原因：**
- config.yaml 中 Prometheus 地址无法访问（网络不通）
- Python 进程异常退出（查看终端日志）

---

### Q17: 指标编辑按钮（Modal 弹窗）不弹出

**可能原因：** 旧版本浏览器或 JS 报错导致事件未绑定。

**解决：**
1. 刷新页面（Ctrl+F5 强制刷新，清除缓存）
2. 换用 Chrome / Edge 等现代浏览器
3. 检查浏览器控制台是否有 JS 错误

---

### Q18: 报告列表为空，但 reports/ 目录下有文件

**可能原因：** 报告文件命名格式不符（正则不匹配）或超过保留天数已被归档。

**解决：**
1. 检查 `reports/` 目录下的文件名格式（应为 `YYYY-MM-DD-HHMM.md` 或 `.html`）
2. 在 Web UI → 巡检报告 → 报告设置，增大「报告保留天数」

## 第六章 多机房配置

### Q19: 多机房巡检时，某个机房始终显示「采集失败」

**排查：**
```bash
# 手动测试连通性
curl http://该机房Prometheus地址:9090/-/healthy
```

**常见原因：**
- 跨网络/VPN 隔离，巡检平台服务器无法访问该机房地址
- config.yaml 中 `sites` 字段地址填写错误

---

### Q20: 如何为每个机房配置独立的 ES 地址？

**config.yaml 配置：**
```yaml
sites:
  - label: "东坝机房"
    prometheus_url: "http://10.1.1.1:9090"
    es_url: "http://10.1.1.2:9200"   # 该机房专属 ES

  - label: "合肥机房"
    prometheus_url: "http://10.2.1.1:9090"
    # es_url 留空 → 使用全局 elasticsearch.url
```

## 第七章 AI 分析

### Q21: AI 分析报错 `overloaded_error` 或响应很慢

**原因：** Claude API 临时过载（常见于高峰期）。

**解决：**
- 等待 1-2 分钟后重试
- 使用 `--skip-llm` 跳过 AI 分析，先生成无 AI 报告
- 切换到内网部署的 OpenAI 兼容模型（在系统设置 → AI 分析中配置）

---

### Q22: AI 分析输出乱码或格式异常

**原因：** 模型输出未完整或 Markdown 渲染问题。

**解决：**
1. 检查 `config.yaml` 中 `llm.model` 字段是否填写了有效的模型名
2. 查看 `reports/` 目录中的原始 `.md` 文件内容是否正常

---

## 第八章 通知

### Q23: 钉钉 / 飞书通知未收到

**排查：**
1. 验证 Webhook URL 是否正确（在对应 App 中重新生成一个）
2. 检查 `.env` 文件或环境变量中 Webhook 变量是否设置
3. 在配置后执行一次带通知的巡检：`python3 -m src.main inspect --skip-llm`

---

### Q24: 企业微信群机器人消息发送失败

**现象：** 日志报 `93000: invalid webhook` 或 `45033`。

**解决：**
- 确认 Webhook URL 未过期（企业微信机器人 Webhook 有效期需在管理后台确认）
- 确认消息内容不超过 4096 字节（可在通知设置中开启「摘要模式」）
